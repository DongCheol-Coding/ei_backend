## 5️⃣ 프로젝트 소개 (Architecture & Design)

동철코딩은 Spring Boot 기반 교육 플랫폼으로,
계층형 아키텍처(Layered Architecture) 위에 **도메인 모델 패턴(Domain Model Pattern)**을 적용하여 개발된 모놀리식 애플리케이션입니다.

---

🔹 아키텍처

3계층: Controller → Service → Repository

도메인: 회원, 강의, 결제, 마이페이지, 채팅을 단일 애플리케이션 내에서 관리

운영: Nginx 리버스 프록시, /actuator/health 헬스체크, Port Switching 기반 무중단 배포

---

🔹 도메인 모델 패턴

User 엔티티에 validatePassword(), softDelete(), bumpTokenVersion() 등 비즈니스 규칙 캡슐화

단순 데이터 보관이 아닌, 풍부한 도메인 모델로 불변식(invariant) 보장

---

🔹 영속성 계층

Spring Data JPA Repository로 데이터 접근 추상화

Specification<User> + @EntityGraph로 동적 검색과 N+1 제거 등 조회 성능 최적화

---

🔹 표현 계층

UserDto.Request / UserDto.Response로 입출력 분리

MapStruct로 DTO ↔ Entity 변환 자동화(반복 코드 제거)

---

🔹 인증 및 보안

JWT 기반 Stateless 인증(AccessToken + RefreshToken)

JwtAuthenticationFilter로 매 요청 인증/인가 처리

쿠키 정책: HttpOnly + Secure + SameSite=None

소셜: Kakao OAuth 2.0 연동 (성공 시 자동 회원가입/토큰 발급)

---

🔹 데이터 관리(삭제/보호)

Soft Delete: isDeleted, deletedAt, deletedReason

회원 탈퇴 시 이메일을 deleted-{id}@user.invalid로 익명화 → 유니크 충돌 방지 & 개인정보 보호

---

## 6️⃣ API 설계 철학 (Design Philosophy)

 목표: 단순 CRUD를 넘어 보안, 데이터 정합성, 성능 최적화, 개인정보 보호, 운영 안정성을 만족하는 실무형 API.

---
🔹 회원가입 & 이메일 인증

문제: 잘못된 이메일/중복 가입

해결: EmailVerification에 인증코드와 요청 JSON 저장 → 만료 검증 후 최종 가입

---

🔹 로그인 & JWT

문제: 세션 기반 확장성 한계

해결: Access/Refresh 구조 + tokenVersion으로 탈퇴/비번변경 시 토큰 무효화

---

🔹 회원 탈퇴

문제: Hard Delete 시 결제/수강 이력 무결성 깨짐

해결: Soft Delete + 익명화로 이력 보존 및 보안 강화

---

🔹 결제 API (KakaoPay)

문제: Ready 성공 후 Approve 실패 시 불일치

해결: PendingPayment로 중간 상태 관리, Approve 성공 시에만 Payment/UserCourse 생성

트랜잭션: Approve 단계에서 @Transactional로 원자성 보장(전부 성공/전부 롤백)

중복/경합: partnerOrderId/tid UNIQUE + idempotent 처리

---

🔹 코스 진행률

문제: 단순 완료 플래그만으로는 세부 진행률 부족

해결: LectureProgress(watchedSec, completed) 저장, 90% 이상 자동 완료

정책: 단조 증가(멱등성) 보장—이전 값보다 작은 업데이트는 무시

---

🔹 관리자 회원 검색

문제: 전체 조회 후 필터링 시 성능 저하·N+1

해결: Specification + @EntityGraph로 조건부 조인 및 N+1 제거

---

🔹 실시간 채팅 (WebSocket + STOMP)

문제: 폴링은 지연/트래픽 부담, 비인증 접근 위험

해결: WebSocket 위에 STOMP 적용

Handshake Interceptor에서 JWT 검증

발행: /pub/chat/{roomId} / 구독: /sub/chat/{roomId}

메시지는 ChatMessage로 DB 영구 저장 → 재접속 시 히스토리 로드

시간은 KST(Asia/Seoul) 기준 저장, 응답에 타임존 명시

---

🔹 전역 예외 & 표준 응답

@RestControllerAdvice로 전역 예외 매핑, 일관된 JSON 응답 포맷

검증/파싱(400), 인증/인가(401/403), 리소스 없음(404), 비즈니스 예외(4xx), 서버 오류(500) 분리
